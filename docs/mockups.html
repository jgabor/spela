spela TUI mock-ups

These are design mock-ups for the terminal UI of spela's Rust rewrite. They are not screenshots of working software. Every screen is drawn on a fixed grid of monospace cells, the way ratatui draws a terminal frame, so each layout could be built as shown.

The frame, keys, popups, theme roles and glyphs follow terminal-ux.md. The destinations, rows, Actions menus and exact wording come from the TUI part of parity-inventory.md. The decisions are in README.md. All eight screens use option B, the chosen keys: the basic keys plus ? : / q Q (decision 1). Screens 1 to 7 show the basic keys, which option B keeps. Screen 8 shows the command palette that option B adds. The mouse is on by default (decision 5). Game names and App IDs are real Steam titles. Versions, paths and metrics are made up.

Page keys: 1 to 8 jump to a screen, 9 to the grid check, t cycles the theme (terminal, light, neon).

How to read the grids

Each screen has the same frame. Row 0 is the top bar: the brand tag, the four destinations and the live GPU metrics. Below it one outer box holds the panes, with each pane's title in the top border. The second to last row is the status line, and the last row is the hint bar.

The default page theme is "terminal": the 16 ANSI colours on a dark terminal, so a user's own terminal theme carries over. "light" shows the same roles on a light terminal. "neon" is spela's current truecolor palette. Cells are coloured by role (focus, own value, ok, warning, error, muted), not by a fixed colour.

State never depends on colour alone. Each state also has a word or a glyph. The indicator glyphs come from the Unicode Neutral width class, so they stay one cell wide in every locale.

1. Library with the profile page

Design choices

  • The 7-row logo header and the destination bar are gone. Destinations and live metrics share row 0. That leaves the workspace 8 more rows than the Go TUI at 120x40: 37 rows against 29.
  • The List is 32 cells wide, from min(32, max(w/3, 24)). It holds the Find row, the pinned All games row, then the games. ▪ and ⚑ sit in fixed columns on the right so names line up. The legend sits in the bottom border.
  • The profile page is one scrolling page. The header keeps three lines: the game line with its save state, "Own settings", and the section strip. The DLL part of the game line is dropped here because it does not fit, as today.
  • Rows are label, value, source. Own values carry a magenta ⚑ and normal text. Following values are muted. The focused row is followed by its description.
  • The status line shows the last save on the left in green with ✓, and the save state on the right.
  • The List title is "Scope", as in Go. Go adds the sort only when it is not the default, as in "Scope [Z-A]".

Keys

Focus is on Detail, in Browse. Up/Down move between fields, Left/Right jump to the next section, and Enter opens the picker (screen 2). Space on an own value makes it follow All games. Space again puts the own value back. Tab or Shift-Tab switch pane. Esc goes back to the List. 0 opens Actions, and 1 to 4 switch destination. The digits show in the top bar only in Browse. ? opens Help and / jumps to Find games.

The mouse works too: click a row to move there, double-click to open it, and right-click for Actions.

The hint bar leaves out the destination keys, as the Go footer does. The top bar already shows them.

2. Editing a field with the picker

Design choices

  • The picker opens inside Detail, right under the field it edits. The rows above and below stay visible, so the user keeps their place.
  • The first choice is "Follow All games (balanced)". It names the value the game would follow. An explicit empty value reads "none".
  • The user typed p, so the title reads "jump: p" and the cursor sits on the first match. performance is the only choice that starts with p. With two matches, the same letter again would move to the next one.
  • The row above shows the value under the cursor as it would be saved. "Value before edit" and the ✓ mark what is stored now.
  • The top bar shows the destinations without digits, because digits are text in Edit mode.

Keys

Letters jump. Up/Down choose, Tab moves to Apply and Cancel, Enter applies, Esc cancels. Applying saves at once: the status line shows "Saving..." on the right, then "Saved". A failed write puts the stored value back and says why.

The Go hint uses the arrow glyphs ↑ ↓. The grid writes Up/Down, because arrows are outside the glyph set this page allows. See the grid check.

3. The game's DLLs with an update confirmation

Design choices

  • The DLLs section is the last stop on the section strip. It shows the game facts, the DLL versions, and the DLL actions with their counts.
  • An unavailable action stays in the list, dimmed, with its reason on the next line: "Unavailable: no backup for this game".
  • The confirmation is now a popup over a dimmed workspace, not an in-pane replacement. The user can still see which game and which DLL it is about.
  • The text is unchanged: "1 DLL target(s)", one line per target with the path under it, and "Backup:". Cancel has focus first.
  • Cyberpunk 2077 has DLSS 310.4.0 while the manifest's latest is 310.5.3. DLSS-G and DLSS-D are current. So "Update DLLs (1 file)".
  • The in-pane hints "Tab: Focus DLL controls" and "Choose action · Enter Update DLLs" move to the hint bar, like every other hint. The hint bar writes key label pairs without the colon, as terminal-ux.md asks. So these e2e strings change, and so do Enter: Edit value, Enter: Open selection and Enter: Batch actions. terminal-ux.md's list of changed strings does not name them yet.

Keys

Left/Right choose a button, Enter activates it, and Tab moves into the body to scroll a long target list. Esc cancels, which is new: today Esc is a no-op here. Esc never confirms. Cancelling writes "DLL update cancelled, no operation ran".

The Go TUI writes the target as "310.4.0 → 310.5.3". The grid writes "->", because → is outside the allowed glyph set.

4. The Actions popup

Design choices

  • 0 opens Actions for the current context. The title says where: "Actions · Library · list". The popup sits on the right, so the list it acts on stays visible behind the dim. With the reasons it needs 80 cells, so at 120 columns it starts at column 38, still clear of the List.
  • The rows are today's rows for Library with List focus, in today's order. Unavailable rows are dim and keep their reason after a dot, such as "· no selected filtered games".
  • A row with a letter key shows it on the right: / for Search games, ? for Help and q for Quit.
  • The cursor starts on the first available row. The Close row stays, so a Tab user keeps a path out.
  • The three Layout rows are left out. Decision 3 drops the Compact and Focused layouts. Screen 6 drops the Compact mode setting to match.

Keys

Up/Down choose and wrap, Enter runs an available row, Tab moves to Close, and Esc closes. Help and Quit are rows here, as today, and also have their own keys. Quit waits for pending saves. Ctrl-C still quits at once from anywhere.

5. Monitor with an active alert

Design choices

  • The top bar and the Monitor read the same buffers. There is one 2 s poll on a worker, and the UI only draws the result.
  • The highest alert shows in the top bar as a glyph and a word: "⚠ Power limited". The List shows "⚠ 1" on its Alerts row. Selecting Alerts lists it with the full message and the recovery hint, as in Go.
  • Sparklines hold the 20 samples of today's ring buffers. Temperature uses the thermal scale. Power is coloured sample by sample by its ratio to the limit, so 318W of 320W reads orange in neon and yellow in the 16-colour theme.
  • Gauges use full blocks and ░ only. The partial blocks the Go TUI uses are left out to keep the glyph set small.
  • The status line carries the release notice on the right, in the Go wording that parity section 17 keeps: "Spela v0.9.0 is available (you have v0.8.2)". terminal-ux.md shortens it to "spela v0.9.0 is available", which its own rule that other strings stay does not allow. One of the two needs to change.

Keys

Focus is on the List. Up/Down pick GPU, CPU or Alerts. Enter opens the selection in Detail, and Tab switches pane. Monitor has no groups, so Left/Right do nothing on its List and are not hinted. ? opens Help.

6. Settings

Design choices

  • The List shows labels only, as today. The groups stack in one column and the current group opens below its name, so the user sees every group and where they are.
  • Detail shows the option's title, value, save state and description. The "Choices" line is new: it shows where the next Space goes.
  • Display holds "Confirm destructive actions". "Compact mode" is gone, because the config migration drops compact_mode (decision 3). Theme (terminal, neon, mono), Mouse and ASCII glyphs join Display. Their labels are provisional: no doc names them yet.
  • Detail also shows the default, 24 hours, from the Go config defaults.
  • The save reached disk, so the status line says "Saved: Refresh interval 24" in green with ✓.

Keys

Focus is on Detail, on a cyclic option. Space picks the next value and saves at once. Detail has no Up/Down here, and Enter only opens an editor on path and list options, so neither is hinted. On the List, Left/Right change group and Up/Down change option. Esc goes back to the List. ? opens Help.

7. Narrow layout, 80 by 24

Design choices

  • Under 100 columns or 30 rows there is one pane, titled "▸ Detail" or "▸ List". Tab shows the other one, and the hint bar says so.
  • The header, the section strip and the focused row with its description all fit. The page scrolls to keep the focused row and its notes in view, and the thumb on the border shows where.
  • The hint bar drops lower-priority hints first. "0 Actions" and "Tab List" always stay. Here "Left/Right Section" and "Esc List" were dropped.
  • An alert is active. The destinations with digits end at column 58, which leaves 19 cells. Even after dropping the sparkline, CPU and power, "GPU 71° 98% ⚠ Power limited" needs 28. So this grid drops util and the GPU label next and keeps the temperature: "71° ⚠ Power limited" starts at column 60, two cells after the destinations. The alert word is never dropped. terminal-ux.md does not state this rule yet.

Below the minimum

Under 80x24 a bounded prompt replaces the screen: "Resize terminal", "Spela needs at least 80x24" and "Current size: WxH". Only Ctrl-C works there.

8. The command palette chosen

Design choices

  • This is part of option B, which the user chose on 2026-10-25 (decision 1). It reverses the basic-key rule from 2026-10-14 and PLAN.md's ban on a palette.
  • : or Ctrl-K opens one fuzzy list over every Actions row, game and setting, from every destination. Matched letters are highlighted.
  • A row shows its key when option B has one, such as 2 for DLL Catalog. Most rows have none, because Actions rows are only reachable through 0.
  • Every basic key still works. Option B adds ? Help, / Find, q back then quit, and Q quit now.

Keys

Typing filters. Up/Down move, Enter runs the row, and Esc closes. An unavailable row would show its reason, as in Actions.

Actions stays the menu for the current context, with its reasons. The palette is the fast path across contexts: one list, typed into, from anywhere.

Grid check

When the page loads, a script checks every grid. Each row must hold exactly the declared number of cells. No text may be clipped at a pane edge, and no right-aligned text may overlap left text in the top bar or the status line. It also reports text written over other text. Only printable ASCII, box drawing (U+2500 to U+257F, which includes the ┃ scroll thumb), the Neutral glyphs ▸ ⚑ ▪ ✓ ✗ ⚠ ⋯, the blocks ▁ to █ and ░, and the two accepted exceptions · and ° may appear. It also measures each rendered row against the cell width, which catches glyphs that fall back to a wider font. Results go to the browser console and appear below.

Wording changed to fit the glyph set

The Go TUI prints some characters that are outside this set. The grids use these stand-ins. A real build would need either these stand-ins or a wider glyph set in terminal-ux.md.

  • Arrow keys ↑ ↓ ← → in hints are written Up/Down and Left/Right.
  • → between versions ("310.4.0 → 310.5.3") is written "->".
  • The ellipsis … in "Saving…" is written "..." (⋯ is kept for truncation).
  • The text cursor ▏ is drawn as one reverse-video cell.
  • The Monitor heading prefix › is dropped. It is Neutral width, but it is not in terminal-ux.md's glyph set, and the pane title already names the section.
  • Gauges use █ and ░ only, without the partial blocks ▏ to ▉.

What these mock-ups cannot show

  • Speed. The budget is p99 under 8 ms from key to flushed bytes for a local action. A still picture cannot show that.
  • The save sequence over time: "Saving..." on the right of the status line, then "Saved", or a failure that puts the stored value back.
  • Your terminal's font and palette. A real build uses them, so colours and glyph shapes will differ.
